# ADR-0004：道路走廊纵坡塑形（road corridor grading）

日期：2026-11-19 · 状态：已采纳
关联：扩展 ADR-0003（不推翻；「单一高度权威」与「物件不存 y」两条保留）

> **修订（2026-11-19）**：本文「路口直接贴回原始地形、wsum 1→1.6 smoothstep 过渡」
> 的决策已被 [ADR-0006](ADR-0006-junction-grade-blend.md) 取代。实测该窄带回退在
> 起伏地形上造成十字路口 22m 断崖；新方案改为按高差自适应引道贴回 base。
> 下文路口段落保留作历史记录，实现以 ADR-0006 为准。

## 背景

ADR-0003 上线后，3D 地图编辑器与游戏世界加了地形，暴露四类问题：

- **道路穿地形 / 显示断断续续**：地形大底板是 40m 高度场上的 ~31~60m 粗网格，
  道路条带按 20m 重采样贴地；两套分段线性曲面采样点不同、互相穿插，路面时隐时现。
- **长面几何顶点不足**：拼接路块、长标线只有 4~8 个顶点，坡地上整块斜插进地形；
  取面路（closed）只有一个常数 y，完全不贴地形（ADR-0003 已知限制）。
- **动态实体脱节**：车辆 `y = 0.02 + terrainHeightAt` 只采车身中心、玩家驾驶写死
  `y = 0.02`、行人固定 `y = 0.16`，坡地上穿模或悬空。
- 用户诉求：道路与「放置模型」同理，道路占用的地面应是**平整场地**；但道路是
  长条，不能压成常数高度 —— 必须**随地形起伏**。

## 决策

1. **单一高度权威升级为两层**：
   `terrainHeightAt = baseHeightAt`（40m 网格双线性 + 建筑地基 pads）**+ 道路走廊塑形**。
   新增 `terrain.corridors`（纯数组、随地图 JSON 保存；旧地图缺字段时惰性重算）。
   道路与建筑共用同一套「数据层压平」机制：建筑是常数高度 pad，道路是沿中心线
   的变高 pad。生成时只读 `baseHeightAt`，避免塑形结果污染原始高度场造成自反馈。

2. **纵断面 / 横断面算法**（道路设计简化版，实现在 `world/terrain.js`）：
   - 走廊来源：描边路、取面路、拼接路块、程序化横纵路网（含延伸路）；
   - 中心线按 8m 等距重采样 → 采原始地表 → 滑动平均滤掉 40m 网格折线棱角 →
     前向/后向两遍最大纵坡限幅（默认 8%，编辑器可 2~20% 调）；
   - **纵坡只做轻量平滑 + 宽限坡**：半径 2 的滑动平均 1 遍（只滤掉 40m 网格
     折线棱角），最大纵坡默认 35%（编辑器 5~50% 可调）。不再用 8% 限坡 ——
     那会把山地硬削成缓坡，路面变成高出地面十几米的堤坝。实测路面与原地形
     落差 <0.5m；
   - 横断面：core（含人行道）内恒为 `profile(s)`，横坡 0；core 外 **8m 窄路肩**
     用 smoothstep 接回原始地形（只平整路面本身，不大范围改造地形）；
   - 路口：多条走廊重叠时**直接贴回原始地形**（两条路天然同高），wsum 1→1.6
     间 smoothstep 过渡。此前加权平均会造出超过限值的假陡坎 / 凹坑。另做 4 轮
     「高程一致性松弛」（阈值放宽到覆盖相邻拼接路块的接缝），避免 28 个独立
     路块各自平滑导致接头裂成碎片；取面路 = 常数高度台地（area corridor）。

3. **几何层三件套**（编辑器与游戏运行时读同一个高度函数）：
   - 道路条带 / 路块 / 程序化骨架 / 取面路按 8m 纵向细分并逐顶点贴地；编辑器新增
     `fitGeometryToTerrain`，运行时 `displaceGroup` 自带水平长面细分（只细分水平面）；
   - 新增 `buildRoadBedGeometry`：8m 高密度「路基补丁」覆盖所有走廊影响范围，
     全局格点去重（路口不重叠）、外扩一圈与原地形齐平；
   - 粗网格地形底板（`userData.terrainBed`）在路基范围内微下沉 0.15m —— 只改渲染
     顶点、**不改变逻辑高度**，路面/标线不被粗三角形吞掉。补丁外扩两圈格点，
     粗三角形跨边界时仍有同高过渡带。实测 6m 下沉会在补丁边缘形成可见的
     壕沟 / 路堤（道路看起来悬在地面上），已废弃；底板另加密到 ~21m（编辑器）
     / ~32m（运行时）以缩小插值误差。

4. **动态实体统一表面高度**：新增 `surfaceHeightAt(map, x, z, city)` = 塑形后地形
   + 所在表面层高（描边路 0.18 / 人行道 0.24 / 街廓 0.16）。玩家、AI 车流、行人、
   玩家驾驶全部改用它；车辆与驾驶再按前后两点采样求 pitch 贴合纵坡，长车不再
   一头插地。地标独立组也按落点采样同一高度权威。

5. **性能**：走廊段建 64m 空间索引（WeakMap 派生缓存、不写 JSON）；查询时每条
   走廊只取最近段的一次贡献；细分仅在「有地形 + 有走廊」时启用，平面地图零开销。

## 被否决的备选

- **把道路压成常数高度 pad**：整条路会悬在半山腰或切进山体，违背「随地形起伏」。
- **把高度场网格分辨率提到 8m**：4000m 范围 → 25 万+ 格点，真实高程采样请求量与
  localStorage 体积爆炸；且仍表达不出横坡为 0 的平整路面。
- **每条路单独铺 ribbon + 大地面挖洞**：路口多张 ribbon 共面闪烁、洞边界裁剪复杂；
  改用全局格点去重的单张补丁 + 底板下沉。
- **只加大 polygonOffset / 抬高路面 y**：能缓解 z-fighting，但遮不住底板三角形整体
  高于路面的部分，且视觉高度与实体贴地高度脱节。
- **逐物件存设计高 y**：违反 ADR-0003「物件不存 y」，改地形后需批量回写、易漂移。

## 已知限制

- 路口直接贴原始地形，坡度就等于该处地形坡度（60m 起伏测试地形实测 ~30%），
  这是「随地形起伏」的预期结果，不是算法造出的假陡坎。
- 走廊极密集时路基补丁顶点数上升（4000m 地图 + 2×3 路网实测约 5k 顶点）。
- 相机遮挡碰撞体顶高仍未叠加地形（沿用 ADR-0003 已知限制）。
- 程序化楼体仍是大盒子角点采样（本次由 `displaceGroup` 的水平长面细分改善顶面）。

## 影响

- 地图 JSON：新增 `terrain.corridors`（每条 8m 采样点的 x/z/s/h 数组）与可选
  `terrain.maxGrade`；旧地图零迁移（`City._init` / 编辑器 `_rebuildAll` 都会重算）。
- 建城 / 编辑器重建：+一次走廊生成（O(道路总长/8m)）+ 一次路基补丁构建；无地形
  时完全跳过。
- 回归自测：`walkstreet/temp-test-road-grade.mjs`。
