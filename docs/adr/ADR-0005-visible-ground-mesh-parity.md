# ADR-0005：可见地面网格与路面网格同精度（消除粗网格顶穿）

日期：2026-11-19 · 状态：已采纳
关联：继承 ADR-0003（单一高度权威）、ADR-0004（道路走廊塑形），不推翻，补其渲染层盲点。

## 背景

ADR-0004 把"逻辑高度"（`terrainHeightAt`）做对了：纵断面限坡、横断面 smoothstep、路口融合，
回归测试全部通过。但用户实测仍见三类症状：

- 游戏视角：道路旁一大块深绿色（`outer` 平面 `0x2c322c`）盖住路面，标线只画一半；
- 地图编辑器：横路 / 纵路 / 描边路 / 拼接路"路面显示不全"，路面时隐时现；
- 视觉上路边缘有"突然隆起 / 凹陷的坎"。

诊断脚本 `temp-diag-render.mjs` / `temp-sweep.mjs` 用真实高度场（seed=7, amp=60, scale=600）
模拟渲染层三角形插值，量化结论：

| 可见层 | 网格步长 | 高出路基补丁(8m)的最大值 | 被盖区域 |
|---|---|---|---|
| `outer` | 62.5m（固定 96 段 / 6000m） | **+3.61m** | 18.6% |
| `road` 沥青面 | ~32m | **+1.84m** | 大量 |

根因：**逻辑高度正确，但可见地面的三套网格精度不一致**。`displaceGroup` / `_bendArea`
只在各自网格顶点采样 `terrainHeightAt`，顶点之间按三角形线性插值。地形凹曲面处，
粗网格的线性插值系统性高于真实曲面；层间设计间距只有 0.15~0.65m，远小于 1~3.6m
的插值误差，于是粗平面从下方顶穿精细路面与标线。ADR-0004 假定"加密到 ~21m/32m
+ 0.15m 下沉够用"，但 `outer` 实际固定 96 段、`tessellateFlat` 又因顶点数 >6000 跳过它，
从未被加密——这是原方案的盲点。

参数扫描（3 组地形 × cell × 下沉系数）进一步证明：**加大下沉无法根除**。
下沉函数本身也在粗网格上采样，窄走廊（半宽 ~15m）相对 62.5m 网格采不到峰值；
即使下沉系数 2.0，62.5m 网格仍顶穿 3.7m。只有当网格步长降到 8m（与路基补丁
同格点、同相位）顶穿才消失（-0.11m）。

## 决策

**可见地面在道路影响范围内必须与路基补丁使用同一精度、同一相位的 8m 全局格点网格；
远景底板不得参与道路区渲染。**

1. **逻辑层（`world/terrain.js`）**：纵断面 / 横断面 / 路口算法零改动（已验证正确）。
   - 新增常量 `GROUND_STEP = 8`，`BED_TESS_EDGE` 复用它，避免两处魔法数字漂移；
   - 新增 `buildGroundSurface(x0,z0,x1,z1,step,tile)`：生成覆盖指定范围、顶点严格落在
     `step` 整数倍上的全局格点网格，与 `buildRoadBedGeometry` **同相位、同三角形绕序**
     （`a,c,b` / `b,c,d`）。这是消除顶穿的关键：同一单元内两套网格插值完全相同；
   - `ROAD_BED_DROP` 回退到 0.15m（中途试过 2.2~3.0m，证明无效且造成壕沟）。

2. **游戏运行时（`world/city.js`）**
   - 主可见地面由 `PlaneGeometry` 改为 `buildGroundSurface(bounds±30m, 8m)`，
     逐顶点采样 `terrainHeightAt` 并在走廊内下沉 `roadBedDropAt`（0.15m）；
   - `outer` 远景底板由整张 6000×6000 平面改为**四块环形拼接**，只覆盖主地面之外
     （内边界 = 主地面边界）。这从根上消除了 outer 从下方顶穿道路的可能，
     不需要靠"下沉到 -2.5m"这种不可靠手段；
   - 路基补丁保持 8m 同相位、不下沉、`position.y = 0.02`，
     因此补丁恒高于主地面 0.17m（走廊内）或 0.02m（走廊外）；
   - 标线（`_solid`/`_solid2`/`_dashes*`/`_crosswalks`）y 从 0.018/0.02/0.024
     统一抬到 0.06/0.065，脱离与补丁的近共面。

3. **地图编辑器（`ui/mapEditor3d.js` + `ui/editor3d/meshes.js` + `ui/editor3d/panels.js`）**
   - 地形底板从 `areaGroup` 内移出，改为挂在 scene 根的独立全局格点网格
     （`buildGroundSurface(terrain 范围±40m, 8m)`）。原方案底板受 `areaGroup` 的
     scale/rotation 变换，顶点无法落在 8m 全局格点上，是编辑器顶穿的根因；
   - 路基补丁同样移到 scene 根（其顶点本来就是全局格点，留在 `areaGroup` 会被
     group 平移/旋转二次变换而错位）；两者共用同一材质与坐标系；
   - 主地面走廊内下沉 0.15m，补丁 `lift = 0.04` → 补丁恒高 0.19m；
   - `roadRibbon` 0.08、`stripGeometry` 默认 0.09、拼接路块 0.10，
     全部高于补丁 0.04；
   - 图层显隐 / 地形透明度同步适配独立网格（`groundMesh` / `bedMesh`）。

## 被否决的备选

- **加大路基下沉到 1.6~6m**：ADR-0004 已否决（壕沟 / 路堤）；本次扫描再次证明粗网格
  采样不到窄走廊，下沉再大也顶穿（62.5m + k=2 仍顶穿 3.7m）。
- **只加大 polygonOffset / 抬高路面**：能治标线共面，治不了粗三角形整体高于路面。
- **给粗底板逐顶点按更高分辨率重采样**：等价于把网格加密到 8m，不如直接做。
- **outer 加密 + 整体下沉到 -2.5m**：中途试过，凹曲面超调仍可达 5.8m，不可靠；
  且大范围下沉会在地图边缘形成断崖。最终改成环形不覆盖道路区，从根上消除重叠。
- **删掉 outer 平面**：它是地图边界外的远景填充，删除会在世界边缘露空；
  改环形是保留功能同时消除重叠的最小改法。

## 验证

- `node temp-test-road-grade.mjs` / `temp-test-terrain.mjs` / `temp-test-pad.mjs`：逻辑回归不变；
- `node temp-verify-final.mjs`：5 组地形 × 20 万采样点，主地面 - 补丁最大高差
  **-0.0894m（≤0，顶穿消除）**，走廊内理论固定高差 0.17m；
- `npm run build`：语法 / 引用校验通过；
- 手工：编辑器俯视 + 游戏第三人称检查四类道路连续无断裂、无深绿顶穿、标线完整。
