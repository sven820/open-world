# ADR-0014：暂时禁用地图范围旋转（Cesium 地理对齐场景）

日期：2026-11-20 · 状态：已采纳
关联：受 ADR-0005（地形主网格挂 scene 根、世界 8m 格点）约束；不推翻既往 ADR。

## 背景

3D 地图编辑器「地图范围 · 属性」面板原有 `旋转(°)` 输入（`#ep-rot`，写 `map.area.rot`）。
用户实测：改旋转后**只有地形上的网格跟着转，地形本体、影像、内容都不转**。

根因不是普通渲染 bug，而是坐标系分工：

- ADR-0005 后，地形主网格 `groundMesh`、裙边、路基补丁都挂在 **scene 根**，用世界坐标
  的 8m 全局格点；`areaGroup` 只剩范围网格 / 边框。所以 `areaGroup.rotation.y = a.rot`
  实际只旋转了 `GridHelper`。
- 高度场权威 `terrainHeightAt` / `baseHeightAt` 按 `(x - t.x0) / step` 采样，不读 `rot`。
- Cesium 地理链路全部按 ENU 轴对齐：`lonLatAt`（经纬度换算）、`sampleRealTerrain`
  （真实高程采样）、`syncCesiumCamera`（相机同步）均不读 `area.rot`。
- 因此 `rot` 只影响视觉网格与裁剪多边形（`areaPoly` / `terrainBBox`），**与真实地理对应无关**。

若要让「整张地图一起旋转」（B 方案 / 烘焙旋转）真正生效，需要：道路、物件、地形 pads、
高度场全部绕中心旋转；高度场须双线性重采样（有损、一次性卡顿、多次旋转累积误差）；
且 `roadsX[i].at` / `roadsZ[i].at` 只能表达轴对齐横纵路网，旋转后无法自然表达斜向路网。
非破坏性变换（A 方案：高度场存局部坐标，采样 / 笔刷 / Cesium / 运行时统一做世界↔局部矩阵）
理论上一劳永逸，但对「建地图时对准 Cesium 地球上的实际地物」这一场景并不划算，长期维护
心智负担大。

## 决策

**暂时禁用地图范围旋转参数，地图与 Cesium 的地理对齐通过中心坐标与描边要素对准实现。**

1. **UI**：`#ep-rot` 加 `disabled`，并挂 `data-tip` 说明禁用原因；移除其 `change` 监听，
   面板 hint 补充「通过中心坐标 / 描边要素对准卫星底图」。
2. **数据权威**：`_areaEnsure()` 统一把 `a.rot = 0`，旧地图残留的非零值归零，
   让 `terrainBBox` / `areaPoly` 的裁剪多边形与可见网格保持一致（避免只转网格不转裁剪）。
3. **地理对齐方式**：建图时用范围中心（X/Z 米）与描边要素直接对准 Cesium 卫星底图 / 真实地物；
   范围旋转不参与经纬度、真实高程采样、相机同步任何一环。
4. **未来若必须支持旋转**：走 A 方案（局部坐标 + 统一世界↔局部变换层），**新建一篇 ADR**
   标记本篇 deprecated，不在本篇上改动（ADR 只增不改）。

## 被否决的备选

- **B 方案 / 烘焙旋转**：全要素绕中心旋转 + 高度场重采样，有损且一次性卡顿；
  `roadsX/roadsZ` 无法表达旋转后的斜向路网；多次旋转累积误差会导致坐标数据异常。
- **A 方案 / 非破坏性变换**：理论一劳永逸，但要改采样 / 笔刷 / Cesium / 运行时全场，
  地理对齐场景下收益不抵成本，暂不采用。
- **只禁用 UI、保留数据旧值**：旧 `rot` 仍会让裁剪多边形与可见网格错位，故一并归零。

## 验证

- `read_lints`：修改文件 0 错误；`npm run build`：通过。
- 手工：3D 编辑器选「范围」工具，右侧「地图范围 · 属性」的旋转输入为禁用态并带原因提示；
  旧地图 `rot` 归零后网格与裁剪多边形一致，地形 / 影像 / 内容不再出现「只转网格」的错觉。
