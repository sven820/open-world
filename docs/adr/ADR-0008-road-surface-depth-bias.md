# ADR-0008 路面强制深度偏置消除主地面顶穿

日期：2026-11-19 · 状态：已采纳
关联：扩展 ADR-0005（可见地面网格同精度）、ADR-0007（路面条带横断面同相位）

## 背景

用户反馈：3D 编辑器里道路（尤其十字路口附近）边缘仍有**锯齿 / 斑块**——路面被地形
啃出规则的三角缺口，上一轮 ADR-0007 修好"路带 vs 补丁"后依旧存在。

## 根因（分层隔离实验定位）

用分层隐藏实验（`temp-visual-layer.mjs`）逐层排查，陡峭地形（振幅 220m）+ 道路相位错开（`at=7`）：

| 显示的层 | 路面锯齿 |
|---|---|
| 全部（主地面 + 补丁 + 路带） | **有** |
| 隐藏主地面（补丁 + 路带） | 无 |
| 只留路带 | 无 |
| 补丁染纯红 | 无红色透出（排除补丁透色假设） |

结论：锯齿来自**下沉主地面 `groundMesh` 从下方顶穿路面条带边缘**。

ADR-0005 让主地面在走廊内下沉 `ROAD_BED_DROP=0.15`，但下沉量按 8m 格点采样
`roadBedDropAt = ROAD_BED_DROP * maxW`。当道路 `at` 不在 8m 格点上（相位错开）时，
主地面格点恰好落在路带边缘外，`maxW` 很小 → 下沉不足；陡峭地形下 8m 三角形
线性插值后高于路带边缘，从下方穿出，形成规则锯齿。

ADR-0007 只保证路带与**补丁**同相位，但补丁覆盖范围之外是主地面，这段的顶穿
ADR-0007 管不到。本质上"靠高度余量压住顶穿"是脆弱方案：地形越陡、相位越错，余量越不够。

## 决策

不再依赖脆弱的高度余量，改为**渲染层强制深度偏置**：把路面材质设为不透明 +
写深度 + `polygonOffset`，让路面永远是可见最上层。

改动（均在编辑器侧）：

- `editor3d/meshes.js` `roadRibbon()`：材质 `transparent: opacity<1`、`depthWrite:true`、
  `polygonOffset:true, factor:-2, units:-2`。程序化横纵路唯一调用 opacity=1，恒不透明。
- `editor3d/meshes.js` `matRoad()`：描边路 / 面路材质加同样深度偏置。
- `editor3d/roadTiles.js` `tileMaterial()`：拼接路块材质加同样深度偏置。

四类道路（横路 / 纵路 / 描边路 / 拼接路）一致处理。

### 为什么不闪烁

两条路带在路口交叉时，高度同为 `terrainHeightAt + lift`、材质相同、polygonOffset 相同，
共面且深度值一致，不存在 z-fighting（分层实验中路口交叉渲染稳定）。旧版用
`transparent + depthWrite:false` 本是为规避交叉 z-fighting，但代价是无法压住地面顶穿；
新版靠"同高同 offset"解决交叉，同时获得抗顶穿能力。

游戏运行时不受影响：`world/city.js` 的路面是画在 8m 同相位主地面上的纹理，没有独立
悬浮路带，ADR-0005 已验证顶穿消除。

## 备选方案（否决）

- **加大主地面下沉 / 扩大下沉包络**：相位错开时格点采不到峰值（ADR-0005 已验证加大下沉无效），否决。
- **只抬高路带 lift**：地形起伏数米时治标不治本，路面悬空、与标线脱节，否决。
- **主地面也按 8m 细分到与路带完全同相位**：主地面覆盖整张地图（数十万顶点），
  为局部路缘全局加密代价过高，否决。
- **polygonOffset 只给路带、保留 transparent+depthWrite:false**：半透明不写深度无法
  稳定压住地面，否决。

## 验证

- 分层隔离：隐藏主地面 / 只留路带 / 加深度偏置三种情况均无锯齿，锁定主地面顶穿；
- 陡峭地形（振幅 220m）+ 相位错开 + 俯视：`layer-1-all-zoom2.png` 路面边缘完全平滑；
- 四类道路综合（`temp-visual-allroads.mjs`）：横纵路十字、描边路、拼接路块均无顶穿锯齿；
- 浏览器几何实测（`temp-verify-ribbon.mjs`）：路带顶点恒高于补丁 0.04m（ADR-0007 不回退）；
- `npm run build` + 逻辑回归（road-grade / terrain / pad / verify-final）全通过。
